# 变电站 · 设备巡检与两票管理

以「两票（工作票 / 操作票）」为核心的变电站运行管理系统。演示录屏用，一键起停。

## 快速开始

```bash
./start.sh        # 首次构建并启动；之后秒级启动
./stop.sh         # 暂停（不删容器）
./resume.sh       # 恢复
./clean.sh        # 收摊：down -v，彻底清空
```

- 前端：http://127.0.0.1:8284
- 后端：http://127.0.0.1:8384 （健康检查 `/actuator/health`）
- MySQL 3584 / Redis 6584

## 技术栈

后端 Spring Boot 3.3.0 + Java 17 + Spring Data JPA(Hibernate 6.5) + MySQL 8 + Redis；
前端 Vue 3 + Element Plus + Vite。主色 `#e65100`（深橙）。

## 五个业务模块

| 模块 | 内容 |
| --- | --- |
| 变电站与间隔 | 变电站、电压等级、间隔（主变/出线/电容器/母联），间隔状态：运行/热备/冷备/检修 |
| 设备台账 | 主变、断路器、隔离开关、CT/PT、避雷器；编号、型号、投运日期、上次检修日期、状态 |
| 巡检与缺陷 | 巡检计划、巡检记录、缺陷（紧急/重大/一般，发现时间、限期消缺日期、闭环状态） |
| 工作票 | 票号、工作负责人、停电范围、签发/许可/终结三审、开工与终结时间；**安全措施逐项执行闭环**（见下） |
| 操作票 | 操作任务、操作步骤序列（按顺序逐条执行、可登记失败并在原步重试）、每步执行人与执行时间 |

## 安全措施逐项执行闭环（工作票核心）

旧版安全措施只是一段文字，无法核验现场是否装设、何时拆除、与倒闸操作是否一致。
现把每条措施拆为独立记录并走完生命周期：

```
PENDING 待执行 ──装设/合上确认──▶ INSTALLED 已执行
   ──许可人通知拆除──▶ TO_REMOVE 待拆除 ──拆除/取下确认──▶ REMOVED 已拆除
```

- **每条措施记录**：类型（接地线 / 接地刀闸 / 遮栏 / 标示牌 / 其他）、所在间隔、具体位置、
  要求动作、是否需拆除、装设人/装设时间、拆除人/拆除时间、当前阶段；
  并绑定「装设对应」与「拆除恢复对应」的操作票步骤号。票面表格用四种颜色清楚展示
  **待执行 / 已执行 / 待拆除 / 已拆除**，列表卡片也有四阶段计数徽标。
- **许可双闸门（两侧同时满足，否则逐项指出卡点并禁止许可）**：
  1. 工作票侧：所有实物措施（接地线/接地刀闸/遮栏/标示牌）已逐项装设确认；
  2. 关联操作票侧：同一间隔关联操作票中对应的装设步骤均已执行；
  「保持安全距离/绝缘工具/专人监护」等作业方法类（其他·无需拆除）不强制绑定倒闸步骤。
  只勾选工作票侧措施、或只校验工作票不核对操作步骤，都不能许可。
- **终结双闸门**：需拆除措施全部拆除确认 + 关联恢复操作票对应步骤全部执行，
  否则逐项列出剩余拆除/恢复卡点并禁止终结。
- **已许可后不得直接删改措施**：现场变更必须先「撤回许可」——
  已装设措施保留、待拆除/已拆除项回置为待执行，许可人/许可时间与历次装拆痕迹全部保留；
  再「现场变更」某条措施时，原行置为「已变更作废」留痕（装拆人时间不抹掉），
  同序号另起新版本号回到待执行重新走闭环；也可撤回后补充新增措施。重新许可需再次通过双闸门。
- **作废**：票面冻结，措施与签字痕迹保留，刷新/重新进入仍显示真实阶段与下一步可做什么。
- **操作失败**：倒闸步骤可登记失败（记录失败人/时间/原因），失败步停在原位、后续步骤不可越过，
  在原步重试成功后才能继续；安措闸门会把关联的失败步骤作为卡点展示。
- **并发**：所有票面推进（签字、撤回、装设/拆除确认、步骤执行）都先取票面行级悲观锁并做状态重检。
  两名值班员同时确认同一条措施或同时许可时只有一次有效推进，后提交者看到的是最新结果，
  不会产生重复执行记录，也越不过尚未完成的项目。
- **留痕**：`safety_measure_log`（编制/装设/拆除/变更/撤回回置，只增不改）与
  `work_ticket_event`（签发/许可/撤回/通知拆除/终结/作废事件流水）全程可追溯。

## 数据访问路线（本仓技术标识）

1. **存储过程**：`@NamedStoredProcedureQuery` + `@Procedure`
   - `sp_defect_summary`：统计各变电站当月缺陷数与消缺率
   - `sp_equipment_summary_by_voltage`：按电压等级汇总设备台数与待检数
   - `sp_next_work_ticket_no`：一键生成工作票票号并回写

   定义见 `backend/src/main/resources/procedures.sql`，由 `ProcedureInitializer`
   （ApplicationRunner）在启动时经 DataSource 执行。之所以不放 `mysql/schema.sql`：
   那是构建期在 MySQL 容器里跑的，过程体里的 `;` 会被客户端截断。
2. **手写 JPQL `@Query`**：缺陷超期排行、两票状态统计、时间轴按天票量等。

## 业务规则（抛 `BizException`，前端直接弹中文提示）

- 倒闸操作步骤必须按顺序执行，跳步时提示「应先执行第 N 步」；操作失败停在原步、不可越过，可重试
- 工作票签发人 / 许可人 / 终结人三人不得为同一人
- 缺陷超期未消缺，不允许终结该间隔的工作票
- 设备处于运行状态的间隔，不允许下达检修工作票
- 许可前：安措逐项装设确认 与 同一间隔关联操作票对应装设步骤，两侧均完成才放行，否则逐项指出卡点
- 终结前：需拆除安措全部拆除 与 关联操作票恢复步骤全部完成，两侧均完成才放行
- 已许可后不得直接删改安措：须先撤回许可，变更项版本化留痕并回到待执行，历史确认记录不抹掉
- 并发确认/并发签字经行级悲观锁串行化，只有一次有效推进，后提交者看到最新结果、无重复记录

## 前端四个页面（顶部时间轴导航 + 四种操作范式）

1. **间隔平面示意图**：SVG 母线 + 各间隔格子，按四种状态着色，点格子弹 popover 直接登记缺陷
2. **两票票面预览 + 三审签字**：A4 票面要素 + 安全措施逐项确认表（类型/间隔/位置/动作/装拆人时间/阶段/关联操作步骤），
   许可、终结双闸门卡点直接列在票面上，底部「签发 → 许可 → 通知拆除 → 终结」按真实阶段点亮，
   支持撤回许可、现场变更（版本化留痕）、作废与事件/痕迹追溯
3. **倒闸操作步骤勾选器**：竖向步骤列表按顺序勾选，右侧实时预览执行进度与执行人
4. **缺陷超期排行 + 消缺闭环**：横向排行条，前三名标红，展开后「登记 → 派工 → 处理 → 验收」

